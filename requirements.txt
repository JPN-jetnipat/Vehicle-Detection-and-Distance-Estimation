# torch/torchvision/ultralytics/numpy are pinned exactly to Japan's

# shared 2026-08-17). This is the actual fix for the version-drift problem
# behind the model.val() vs eval_detections.py mAP discrepancy (up to 6pp on
# low-instance classes like truck/bus - see the evaluator debate/hybrid
# decision). Loose pins don't solve that; identical pins do.
#
# OPEN ITEM: Japan's own two snapshots disagreed before - an eval run showed
# ultralytics==8.4.120, a later pip freeze showed 8.4.65 (pinned below, and
# repeated in his latest shared requirements.txt, so it looks like the real
# current one). Worth a one-line confirm from him before a long training run:
# `pip show ultralytics | grep Version`.
#
# Install order matters - torch/torchvision need the CUDA build, which plain
# `pip install -r requirements.txt` alone won't get you:
#   1. nvidia-smi                                    # confirm CUDA 12.4 still current
#   2. pip install torch==2.12.0 torchvision==0.27.0 --index-url https://download.pytorch.org/whl/cu124
#   3. pip install -r requirements.txt                # torch/torchvision already satisfied, skipped
#   4. python -c "import torch; print(torch.__version__, torch.cuda.is_available())"   # expect True
#
# Kaggle note: Kaggle notebooks ship their own torch build - do NOT reinstall
# torch there; install only the non-torch deps below.
